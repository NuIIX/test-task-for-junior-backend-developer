## Реализация периодических задач (Recurring Tasks)

Для реализации периодических задач выбран подход **Pre-generation (предгенерация)** через механизм Шаблонов (Templates) и Воркера (Worker).

### Почему именно этот подход?

Медицинскому персоналу важно видеть реальные физические задачи в своем плане на неделю или месяц вперед. Это дает возможность перенести, отменить или изменить статус (например, `done`) для _одной конкретной итерации_ задачи (например, обход в среду), не ломая при этом общее расписание.

**Архитектура:**

1. При отправке POST запроса с полем `recurrence_rule`, задача помечается как `is_template = true`.
2. Система мгновенно генерирует дочерние задачи (`parent_task_id`) на горизонт планирования (30 дней).
3. В фоне работает процесс (Worker), который запускается раз в сутки и досоздает задачи, чтобы горизонт планирования всегда был заполнен.
4. Дочерние задачи идемпотентны. Используется связка `ON CONFLICT (parent_task_id, scheduled_date) DO NOTHING`.

**Граничные случаи (Edge Cases), которые были учтены:**

- **Проблема конца месяца (29/30/31 числа):** Если установлено ежемесячное повторение 31-го числа, а в месяце (например, апреле) 30 дней, задача автоматически планируется на последний день месяца (30-е).
- **Обновление правил (PUT):** При изменении правила периодичности у шаблона, система автоматически удаляет все будущие невыполненные сгенерированные задачи и перестраивает их по новому правилу. История (выполненные задачи) сохраняется.

# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

## Swagger

Swagger UI:

```text
http://localhost:8080/swagger/
```

OpenAPI JSON:

```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
